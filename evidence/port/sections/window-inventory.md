# B. WINDOW INVENTORY AND NATIVE WINDOW OWNERSHIP

## Evidence convention

`[VERIFIED]` means read from an admitted exact source or unambiguous target disassembly/import evidence. `[INFERRED]` means taken from a preserved open-function draft, caller/callee evidence, or a supported cross-version mapping. `[UNKNOWN]` means the inspected evidence does not settle the field. In tables, each cell carries its own status; the citations identify the evidence to check. Win16 source paths below are relative to `D:\Prog\simantw_recon`; DOS paths are relative to `D:\Prog\simant_recon`.

## Shared native-window contract

- **[VERIFIED] Logical identity:** normal game HWNDs are stored in `win_hwnd[ID >> 8]`; `win_Open` is passed packed IDs such as `0x0000`, `0x0100`, etc. `SetProp(hwnd,"INDEX",ID)` binds the full logical ID to each generic HWND. Evidence: `win_Open` at `SIMTWO_MODULE:CA2E` (1385 bytes; draft `evidence/recovery/drafts/win_Open/340a8dee76c6.c:89-230`), `INDIRECTDLGPROC` at `SIMTWO_MODULE:DDD2`, and exact `win_IsWinInFront` in `src/recovered/win_IsWinInFront-c38b403794.c:10-31`.
- **[VERIFIED] Shared classes:** `InitApplication` at `SIMANT_MODULE:3DD0` (exact source `src/recovered/InitApplication-a2dc0a1ce1.c:41-79`) registers `AntRoot`, `GenericWindow`, and `RibbonWindow`; all three use `MainWndProc`. `AntRoot` has class style `0`, icon resource `"SimAnt"`, arrow cursor, background `0x0d`; `GenericWindow` and `RibbonWindow` use class style `0x1008` (`CS_BYTEALIGNCLIENT | CS_DBLCLKS`), no class menu, and backgrounds `6` and stock object `1`, respectively.
- **[VERIFIED] Frame hierarchy:** `InitInstance` at `SIMANT_MODULE:3C8A` (exact source `src/recovered/tu_simant_01B6_DoUserButtonUpdate_15_reviewed-db9484741a.c:1024-1104`, literals at `:356-366`) creates `mainRootWnd` as top-level `AntRoot` style `0x02CF0000` (`WS_CLIPCHILDREN | WS_OVERLAPPEDWINDOW`), then creates `rootWnd` and `ribbonBarWnd` as `AntRoot`/`RibbonWindow` children of `mainRootWnd`, each style `0x52000000` (`WS_CHILD | WS_VISIBLE | WS_CLIPCHILDREN`). **[VERIFIED]** `mainRootWnd` and `rootWnd` are separate globals rather than logical slots; **[INFERRED]** the best `WINMAIN` draft also binds `ribbonBarWnd` into `win_hwnd[0x22]` for logical ID `0x2200` (`evidence/recovery/drafts/WINMAIN/8c89fbd1b287.c:175-190`).
- **[INFERRED] Generic HWND kind:** `win_Open` calls `CreateWindow("GenericWindow", "Generic Window", style, ..., rootWnd, ...)`; target style construction only sets low-order style bits and never sets `WS_CHILD` (`0x40000000`) or `WS_POPUP` (`0x80000000`). Under Win16 `CreateWindow` conventions this is an owned, overlapped top-level window associated with `rootWnd`, rather than a child window. Evidence: `win_Open` draft above and Win16 constants in `toolchain/sdk310/INC/WINDOWS.H:2934,2936,2978-2986,3009-3010,3328-3330`. SDK semantic reference: [Windows 3.1 SDK Programming Guide](https://bitsavers.trailing-edge.com/pdf/microsoft/windows_3.1/Microsoft_Windows_3.1_SDK_1992/PC28919-0492_Guide_to_Programming_199204.pdf) (child windows use `WS_CHILD`); [CreateWindow reference](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createwindoww) (parent argument supplies parent/owner context).
- **[INFERRED] Open/show/reuse:** `win_LoadAllWindows` at `SIMTWO_MODULE:C806` loads metadata and clears HWND slots; HWNDs are created lazily by `win_Open` when a slot is empty. A populated visible slot is brought to top; a populated hidden slot is repositioned, shown, invalidated, and updated; an empty slot is created, tagged with `INDEX`, then shown. Evidence: `evidence/recovery/drafts/win_LoadAllWindows/fcc0028f9bdb.c` and `evidence/recovery/drafts/win_Open/340a8dee76c6.c:89-230`; USER imports in `build/context/win_Open.json` include `CreateWindow`, `SetProp`, `ShowWindow`, `BringWindowToTop`, `SetWindowPos`, `InvalidateRect`, and `UpdateWindow`.
- **[INFERRED] Object loading and layout:** `win_LoadWindow` at `SIMTWO_MODULE:C662` loads the resource-backed data for a logical ID and initializes its object/pointer state; `win_Recalc` at `SIMTWO_MODULE:E6E2` recalculates logical object rectangles and anchor/automatic sizing before `win_Open` applies native frame/ribbon metric adjustments. Evidence: drafts `evidence/recovery/drafts/win_LoadWindow/ae79989982f6.c`, `evidence/recovery/drafts/win_Recalc/868bd0db1b17.c`, and `evidence/recovery/drafts/win_Open/340a8dee76c6.c:89-230`.
- **[INFERRED] Close is hide/reuse:** `win_Close` at `SIMTWO_MODULE:CF98` (168 bytes; draft `evidence/recovery/drafts/win_Close/cfc32202bfaa.c:28-58`) clears the logical open flag and calls `ShowWindow(hwnd, SW_HIDE)`; it selects a remaining top window and sends `WM_NCACTIVATE (0x0086)` via `SendMessage`. The target's imported USER calls do not include `DestroyWindow`, so ordinary close appears to retain the HWND in its slot. `WM_CLOSE (0x0010)` for a generic window is routed through its `INDEX` property to `win_Close` in the `MAINWNDPROC` draft (`evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c:403-422`). Exact HWND destruction during process shutdown is **[UNKNOWN]**.
- **[VERIFIED] Z-order query:** `win_IsWinInFront` starts at `GetTopWindow(rootWnd)`, skips invisible windows with `GetNextWindow(hwnd, GW_HWNDNEXT=2)`, follows owner with `GetWindow(hwnd, GW_OWNER=4)`, and compares `INDEX` to the requested ID (`src/recovered/win_IsWinInFront-c38b403794.c:10-31`). `win_ToTop` calls `BringWindowToTop(win_hwnd[ID >> 8])` (`src/recovered/win_ToTop.c:1-7`). `win_IsWinOpen` is **[INFERRED]** to mean non-null slot and `IsWindowVisible`, based on `evidence/recovery/drafts/win_IsWinOpen/3d9036c5feb0.c` (target `SIMTWO_MODULE:C256`, 49 bytes; source stub `src/recovered/win_IsWinOpen.c:1-14`).
- **[VERIFIED] Exposure is frame containment:** `win_IsWinExposed` checks whether the window's client rectangle, converted to screen coordinates, is contained by the `rootWnd` rectangle using `IntersectRect`/`EqualRect`; this does not test occlusion by other windows (`src/recovered/wf_win_IsWinExposed-22083a86a9.c:30-51`, target `SIMTWO_MODULE:C102`).
- **[INFERRED] Painting and common events:** all registered game classes dispatch to `MainWndProc`. Its best draft routes `WM_PAINT (0x000F)` for generic windows through `PaintStuff` and uses `win_drawHooks[ID >> 8]`; it has a distinct ribbon paint branch. The `WM_SIZE (0x0005)` draft handles frame/root/ribbon geometry and the edit window; other logical window resize policy is not established. Evidence: `evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c:301-401`; target is open at `SIMANT_MODULE:2930` (4953 bytes). Treat all detailed `MainWndProc` behavior as inferred until exact source is admitted.
- **[VERIFIED] Hook table:** `InitApplicationWindows` exact source registers 11 hook mappings after `win_LoadAllWindows`: `0x000 win_DrawEditWindow`, `0x0100 win_DrawMapWindow`, `0x1500 win_DrawHistoryWindow`, `0x1200 win_DrawModeWindow`, `0x1300 win_DrawCasteWindow`, `0x1900 win_DrawYardWindow`, `0x0500 win_DrawInfoWindow`, `0x1E00 win_DrawPictureWindow`, `0x0400 win_DrawEndGameWindow`, `0x1D00 win_DrawExamineWindow`, `0x1800 win_DrawScoreWindow`. Evidence: `src/recovered/wf_InitApplicationWindows-84f4e064cb.c:20-35`, target `SIMANT_MODULE:5464`.
- **[VERIFIED] DOS manager:** DOS `win_LoadWindow`, `win_LoadAllWindows`, `win_Open`, `win_Close`, and `win_SetWinDrawHook` are in `D:\Prog\simant_recon\src\root\m20E8.c:36-71,96-140,207-255,259-289,351-354`. DOS has the same resource-backed window/object layout and 45 offset/hook slots (`docs/window-model.md:8-35`), but `win_Open` maintains a logical active stack (`g_5702[]`), recalculates anchors, clips/draws and flushes events; `win_Close` removes the logical window and redraws uncovered content. It has no HWND, USER z-order, or per-window native window procedure. Win16 `win_LockWinHigh` is a no-op (`src/recovered/win_LockWinHigh.c`); DOS calls its lock helper with high-priority flag `1` (`src/root/m23AE.c:192-200`).

### Native dialog and auxiliary procedures

- **[INFERRED] Modal dialog HWNDs:** `INDIRECTDLGPROC` (`SIMTWO_MODULE:DDD2`, 143 bytes; best draft `evidence/recovery/drafts/INDIRECTDLGPROC/9b8767967254.c:1-43`) handles a dialog created outside ordinary `win_Open`: on `WM_INITDIALOG (0x0110)`, it derives a slot from the object ID, stores the HWND in `win_hwnd[]`, sets `INDEX`, and captures the mouse; on `WM_LBUTTONDOWN (0x0201)`, it clears the slot, releases capture, and calls `EndDialog`. `WM_PAINT` delegates to `PaintStuff`. Marked inferred because details cited are from the preserved draft.
- **[INFERRED] Window manager message responsibilities:** `MAINWNDPROC` is the shared proc for `AntRoot`, `GenericWindow`, and `RibbonWindow`. Its draft handles `WM_SIZE 0x0005`, `WM_PAINT 0x000F`, `WM_CLOSE 0x0010`, `WM_ACTIVATEAPP 0x001C`, `WM_MOUSEACTIVATE 0x0021`, `WM_NCACTIVATE 0x0086`, `WM_KEYDOWN 0x0100`, `WM_COMMAND 0x0111`, `WM_SYSCOMMAND 0x0112`, mouse messages `0x0200-0x0205`, and palette messages `0x030F/0x0311`; see `evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c`. It routes gameplay input through `DoMouse` and manages capture/focus/z-order; branch-level certainty remains inferred.
- **[INFERRED] Primary Win16 event pump:** `WINMAIN` (`SIMANT_MODULE:3FDA`, 1546 bytes; open draft `evidence/recovery/drafts/WINMAIN/8c89fbd1b287.c:142-153,248-257`) contains the primary `GetMessage`/translate/dispatch loop according to the draft and target imports. **[VERIFIED]** Simulation helper `win_Events` pumps `PeekMessage(...,PM_REMOVE)` then `TranslateMessage`/`DispatchMessage`; it counts mouse down/up (`0x0201/0x0202`) and selected keys (`WM_KEYDOWN 0x0100`, Space `0x20`, Insert `0x2D`) (`src/recovered/tu_simtwo_C32E_win_ObjAddr_20_reviewed-cf86811e02.c:192-210`).
- **[INFERRED] Auxiliary `GTCLIENTWNDPROC`:** separate `_TEXT:7D3E` procedure (138 bytes) handles custom messages `0x03E4/0x03E5` in its best draft and otherwise delegates to `DefWindowProc`; its DDE/Gateway relation is suggested by `GtInitiateDDE` but its host-facing purpose is **[UNKNOWN]**.
