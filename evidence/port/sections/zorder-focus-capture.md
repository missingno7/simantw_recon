# Z-order, activation, focus, capture, and cursor

**Evidence key:** **VERIFIED** means an admitted Win16 source or exact DOS source/model. **INFERRED** means a best Win16 draft or incomplete DOS cursor source. **UNKNOWN** marks a behavior the available evidence does not settle.

## Ordering and front tests

- **VERIFIED — DOS authority:** DOS keeps its own logical order in `g_5702[]`, with the front window at `[0]` and `0x8000` as the terminator. `win_IsWinInFront(win)` is only `g_5702[0] == win` (`simant_recon/src/root/m22BF.c:501-506`, DOS address `root:22BF:0A22`; global noted in `simant_recon/docs/window-model.md:32-35`). `f_1E57_00B1` moves a window ID to `[0]` and removes its old occurrence (`simant_recon/src/root/m1E57.c:74-91`). Closing removes an ID from the stack (`clip_KillWin`, `m1E57.c:95-110`).
- **VERIFIED — Win16 delta:** The Win16 `win_*` layer maps a packed game window ID to `win_hwnd[id >> 8]`; `win_ToTop(id)` passes that HWND to `BringWindowToTop` (`src/recovered/win_ToTop.c:1-7`, `SIMTWO_MODULE:D41E`). USER's `BringWindowToTop` also activates a top-level window (or a child's top-level parent), so Win16 raising couples z-order and activation ([BringWindowToTop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-bringwindowtotop)). `INDEX` window properties map an HWND back to the game ID (`src/recovered/win_IsWinInFront-c38b403794.c:10-31`, `SIMTWO_MODULE:C19E`).
- **VERIFIED — Win16 enumeration:** `GetTopWindow(rootWnd)` starts at USER's top child; relation `2` (`GW_HWNDNEXT`) walks down the Z order, relation `3` (`GW_HWNDPREV`) walks up, and relation `4` (`GW_OWNER`) obtains an owner. `MyGetTopWindow` skips invisible HWNDs and returns the owner of the first visible window when it has one (`src/recovered/wf_MyGetTopWindow-8cee2c18ed.c:12-31`). `win_IsWinInFront(id)` performs the same visible-window/owner normalization, then compares `GetProp(hwnd,"INDEX")` with `id` (`win_IsWinInFront-c38b403794.c:10-31`). These are USER relationships, not comparisons against a second Win16 game stack ([GetTopWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-gettopwindow), [GetWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindow)).
- **VERIFIED — Win16 cycle helper:** `_DoNextWindow` walks relation `2` to the last HWND, then relation `3` past owned or hidden HWNDs, and raises the first remaining window (`SIMANT_MODULE:182C`; admitted body in `src/recovered/tu_simant_01B6_DoUserButtonUpdate_15_reviewed-db9484741a.c:846-860`). **INFERRED:** The open `win_Open` draft adds a system-menu “Next” item with Ctrl+F6, and the open `MAINWNDPROC` draft handles `WM_SYSCOMMAND`/`SC_NEXTWINDOW` (`0x0112`/`0xF040`) by another visible/unowned walk (`evidence/recovery/drafts/win_Open/340a8dee76c6.c:203-218`; `evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c:722-740`).
- **VERIFIED — Win16 exposure is geometric:** `win_IsWinExposed(id)` converts the HWND client rectangle to screen coordinates and returns true only if its intersection with `GetWindowRect(rootWnd)` equals the full client rectangle (`src/recovered/wf_win_IsWinExposed-22083a86a9.c:30-51`, `SIMTWO_MODULE:C102`). It does **not** ask whether another sibling obscures the window. DOS has no matching OS-occlusion query in the recovered stack model.

## Activation, focus, opening, and closing

- **VERIFIED — focus API inventory:** The Win16 image imports `SetFocus` once in `MAINWNDPROC`; the audit finds no `SetActiveWindow`, `GetActiveWindow`, or `GetFocus` import (`evidence/port/audit.json`; `MAINWNDPROC` target at `SIMANT_MODULE:2930`). **INFERRED:** The best draft uses private `activeAppFlag` state and does not query a USER-focused SimAnt child to decide game state.
- **INFERRED — app activation:** The best `MAINWNDPROC` draft handles `WM_ACTIVATEAPP` (`0x001C`). On activation it sets `activeAppFlag`, restores the remembered non-client-active window (`WM_NCACTIVATE`, `0x0086`), calls `SetFocus(rootWnd)`, and restores a saved capture if its HWND is visible and the main window is not iconic. On deactivation it releases native capture, saves/disables sound options, changes timer cadence and palette state, and remembers a system cursor (`evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c:435-504`). This is app-level activation, not a `SetActiveWindow`/`GetFocus` policy for each logical window.
- **INFERRED — click-to-activate policy:** In the same draft, for a left-button `WM_MOUSEACTIVATE` (`0x0021`) on a non-root HWND, the handler checks bit `0x40` in the current top window record. With a valid top-window `INDEX` and the bit clear it raises the clicked HWND, sends `WM_NCACTIVATE(1)`, and returns `2` (`MA_ACTIVATEANDEAT`); otherwise it returns `3` (`MA_NOACTIVATE`) (`MAINWNDPROC` draft lines 541-556). The return meanings follow USER's message contract ([WM_MOUSEACTIVATE](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mouseactivate)).
- **INFERRED — show/hide:** The open `_win_Open` draft maps an already-visible logical window to `BringWindowToTop`; it positions and shows an existing hidden HWND, or creates a `GenericWindow`, stores its game ID as `INDEX`, raises it, shows it, invalidates it, and updates it (`SIMTWO_MODULE:CA2E`; `evidence/recovery/drafts/win_Open/340a8dee76c6.c:89-229`). The open `_win_Close` draft clears the game open bit and uses `ShowWindow(hwnd,0)` to hide but retain the HWND; it then raises the next visible/normalized window and posts `WM_NCACTIVATE` (`0x0086`) (`SIMTWO_MODULE:CF98`; `evidence/recovery/drafts/win_Close/cfc32202bfaa.c:28-58`). `MAINWNDPROC` draft maps `WM_CLOSE` (`0x0010`) on an indexed game HWND to `win_Close`; closing `mainRootWnd` instead follows the quit prompt path (`MAINWNDPROC` draft lines 403-422). `win_Zoom` is admitted and uses `ShowWindow(hwnd,3)` (`src/recovered/win_Zoom.c:1-7`).
- **VERIFIED — DOS auto-close contract:** On a DOS click, `f_218D_0451` closes the front window if the click is outside its window rectangle and its record bit `+0x1C & 1` is set. If the front record's `+0x1C & 0x40` is clear, it finds the stack window containing the click and calls `f_20E8_0725` to bring it forward; that helper closes a different front window first when its bit `+0x1C & 1` is set (`simant_recon/src/root/m218D.c:233-257`, DOS address `root:218D:0451`; `m20E8.c:293-309`, DOS address `root:20E8:0725`).
- **UNKNOWN — Win16 auto-close equivalence:** The Win16 open/close and main-procedure drafts show USER visibility, activation, and hide/show behavior, but do not prove that the DOS bit-`1` outside-click auto-close rule is reproduced. The SDL port should retain the DOS rule in shared window logic unless later Win16 evidence establishes a deliberate difference; do not infer auto-close from bit `0x40` in `WM_MOUSEACTIVATE`.
- **VERIFIED — custom versus native dialogs:** `DoScenario` opens logical window `0x200`, takes capture, flushes queued events, and runs a synchronous `win_GetEvent`/abort/Enter loop before closing the window (`src/recovered/wf_DoScenario-496dc7a0ac.c:44-87`). **INFERRED:** This is a modeless HWND under the game manager but modal to that game routine. **VERIFIED — separate native path:** `_FileSelect` imports USER `DialogBox`, and `OPENDLG`/`SAVEASDLG` use dialog-procedure APIs; file selection is a genuine USER dialog path (`evidence/port/audit.json`).

## Mouse capture, polling, and cursor

- **VERIFIED — capture wrapper:** `MySetCapture(hwnd)` saves `captureWnd`; it calls USER `SetCapture` only while the app is active and the main window is not iconic, otherwise it queries `GetCapture`. It accepts the captured HWND only if it has an `INDEX` property (`src/recovered/MySetCapture-a20ced370b.c:16-29`). `MyReleaseCapture` clears `captureWnd` and calls USER `ReleaseCapture` only if `activeAppFlag` is set (`src/recovered/MyReleaseCapture.c:5-12`).
- **INFERRED — mouse-message lifetime:** The best `MAINWNDPROC` draft requests capture on `WM_LBUTTONDOWN` (`0x0201`) when no logical capture exists, dispatches left down/up, left double-click, and right-button-up (`0x0201/02/03/05`) to `DoMouse`, then releases the wrapper capture after `WM_RBUTTONUP` (`0x0205`) (`MAINWNDPROC` draft lines 837-858). Custom dialog/menu routines also take and release capture; e.g. the admitted `DoScenario` routine holds it across its wait loop, and the open `win_DoProxMenu` draft releases it when its menu loop ends. On app deactivation the draft calls USER `ReleaseCapture` but retains `captureWnd`; on reactivation it reacquires that saved HWND if still visible (`MAINWNDPROC` draft lines 463-469, 485-488). This unusual right-up release condition needs confirmation before it is treated as a universal drag rule.
- **VERIFIED — queued events plus polling:** `win_Events` drains the USER queue with `PeekMessage`/`TranslateMessage`/`DispatchMessage` and flags left-button down/up (`0x0201/0x0202`) or `WM_KEYDOWN` (`0x0100`) for Space (`0x20`) or Insert (`0x2D`) (`src/recovered/tu_simtwo_C32E_win_ObjAddr_20_reviewed-cf86811e02.c:192-210`). Separately, exact `StillDown` polls `GetAsyncKeyState`'s high bit for physical mouse buttons `1/2` plus Insert/Space/Delete aliases (`0x2D/0x20/0x2E`), normalizing swapped mouse buttons through `SwapMouseButton` (`src/recovered/wf_StillDown-a90f7d48e5.c:11-36`). The best `ButtonHeld` draft adds a two-tick hold delay and repeated asynchronous samples (`evidence/recovery/drafts/ButtonHeld/16faa4a2fc19.c:21-84`). `DoMouse` also samples modifier/toggle keys and uses asynchronous Ctrl for a click path (`evidence/recovery/drafts/DoMouse/120cd296c0bf.c:99-116`). USER defines the high bit as “currently down”; the low “pressed since last query” bit is not used in these samples ([GetAsyncKeyState](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getasynckeystate)).
- **VERIFIED — native cursor:** `LoadFancyCursor` loads seven resources (`MagCursor`, `RockCursor`, `DigCursor`, `AntCursor`, `FoodCursor`, `DropCursor`, `SprayCursor`); `SetFancyCursor` selects among them by `CurExpTool` for a front map/yard window in game type `3` (the yard-window path also requires Shift) (`SIMANT_MODULE:280E` and `2880`; admitted source `src/recovered/tu_simant_01B6_DoUserButtonUpdate_15_reviewed-db9484741a.c:976-1020`). The import audit contains `LoadCursor`/`SetCursor` but no `ShowCursor` call. **INFERRED:** `MAINWNDPROC` handles `WM_SETCURSOR` (`0x0020`): help mode sets the help cursor; otherwise a client-area hit (`LOWORD(lParam)==1`) over a front map/yard window in game type `3` selects the tool cursor, with Shift required on the yard-window path (`MAINWNDPROC` draft lines 506-539). On app deactivation it sets cursor resource `0x7F02` before restoring the saved cursor on activation (draft lines 474-481); no explicit Win16 mouse-leave handler is evident in that draft.
- **INFERRED — software map cursor is separate:** DOS draws/erases a map cursor through the game's clipped graphics path (`DrawMapCursor`/`EraseMapCursor`, `simant_recon/src/S12/m384C.c:155-189`; the current `DrawMapCursor` body is explicitly a scaffold). Win16 also calls `DrawMapCursor` while repainting. Treat this as a game overlay, not the OS pointer; the native pointer shape is a separate host cursor.

## SDL3 host contract

- **INFERRED — ordering/focus:** Keep a `logical window ID -> SDL_Window*` map and an explicit per-app z-order/visibility list for DOS semantics. Use `SDL_RaiseWindow` for a raise request, but update active state from `SDL_EVENT_WINDOW_FOCUS_GAINED/LOST`; SDL documents that raising is subject to window-manager focus policy ([SDL_RaiseWindow](https://wiki.libsdl.org/SDL3/SDL_RaiseWindow), [SDL_EventType](https://wiki.libsdl.org/SDL3/SDL_EventType)). Do front/owner tests in the game window manager because SDL does not expose the USER sibling/owner traversal used above. Do the `win_IsWinExposed` root-containment test from logical client/root rectangles, not SDL occlusion state.
- **INFERRED — capture:** Map `MySetCapture`/`MyReleaseCapture` to `SDL_CaptureMouse(true/false)` and keep the logical capture ID in shared state. SDL capture is global to the app's current foreground window, may be unavailable on a video target, and is dropped on focus loss; reacquire after focus gain only if the saved logical capture still exists and is visible. Keep capture short-lived around drags, menus, and modal game loops; SDL may auto-capture during button presses ([SDL_CaptureMouse](https://wiki.libsdl.org/SDL3/SDL_CaptureMouse)).
- **INFERRED — event and polling bridge:** Drain SDL events and translate them into the shared game event record, preserving the observed left-button/Space/Insert wake conditions. Continue sampling current input state where `StillDown`/`ButtonHeld` require it; `SDL_GetGlobalMouseState` provides asynchronous mouse state, while `SDL_GetKeyboardState` is updated by event pumping and can miss a press-and-release that happens before the pump ([SDL_GetGlobalMouseState](https://wiki.libsdl.org/SDL3/SDL_GetGlobalMouseState), [SDL_GetKeyboardState](https://wiki.libsdl.org/SDL3/SDL_GetKeyboardState)). Preserve the DOS/Win16 primary-secondary button and keyboard-alias rules in shared input logic.
- **INFERRED — cursor and game logic:** Convert the seven cursor resources to SDL cursor objects and call `SDL_SetCursor` when the help/tool selection changes and on window mouse-enter/leave events; there is no Win16 `ShowCursor` behavior to reproduce. Keep tool choice, help state, front-window selection, object hit testing, auto-close policy, and game-drawn map cursor in shared code ([SDL_SetCursor](https://wiki.libsdl.org/SDL3/SDL_SetCursor); SDL enter/leave events are listed in [SDL_EventType](https://wiki.libsdl.org/SDL3/SDL_EventType)).
