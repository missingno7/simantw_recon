# D. REDRAW / INVALIDATION MODEL

**Evidence tags.** `VERIFIED` means admitted Win16 C, exact DOS C, a resolved import/disassembly fact, or the Win16 API contract. `INFERRED` means the current open draft or a cross-version comparison supports it. `UNKNOWN` marks a point that still affects the SDL host contract.

## Native paint lifecycle

1. **VERIFIED** `InitInstance` creates `mainRootWnd` as the top-level `AntRoot` window (style `0x02cf0000`, property `INDEX=-1`), then creates `ribbonBarWnd` and `rootWnd` as child windows with style `0x52000000`; it calls `UpdateWindow` for both children. See `src/recovered/wf_InitInstance-36ddf2b282.c:46-84` (`InitInstance`, `SIMANT_MODULE:0x3C8A`).
2. **INFERRED, strongly supported by exact imports** `MAINWNDPROC` handles `WM_PAINT` (`0x000f`) specially. The current best draft shows a ribbon-specific branch that does `BeginPaint`, measures and centers "This is the ribbon bar.", fills the ribbon client with stock brush 2, calls `TextOut`, then `EndPaint`. Other indexed game windows go to `PaintStuff`; `INDEX=0xffff` or a missing `rootWnd` returns without that route. `MAINWNDPROC` is still open, so use this dispatch detail as a draft-backed contract, not an admitted reconstruction. See `evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c:385-402`; target entry is `SIMANT_MODULE:0x2930`.
3. **VERIFIED** `PaintStuff` (`GR_MODULE:0x3E92`) sends `mainRootWnd`, `rootWnd`, and invisible windows to `DefWindowProc`. For a visible logical child, it reads the `INDEX` property, stores the HWND in `clipWind`, creates `updateRgn`, copies the HWND's current update region with `GetUpdateRgn(hwnd, updateRgn, FALSE)`, then calls `BeginPaint`. If it gets an HDC, it initializes/selects/realizes the app palette, selects the large font, and calls `win_DrawWindow(objectNumber)`; it then invokes an optional callback, restores selected GDI objects and palette, calls `EndPaint`, deletes the temporary region, and clears `updateRgn`, `clipWind`, and `clipDC`. `MAINWNDPROC` and `INDIRECTDLGPROC` pass a null callback. See `src/recovered/wf_PaintStuff-4a441706dd.c:28-74` and `src/recovered/wf_INDIRECTDLGPROC-3e701072c7.c:25-42`.
4. **VERIFIED** The DOS counterpart has no USER paint message. Its exact `win_DrawWindow` (`root:21FA:08E2`) locks the logical window, runs draw hook phase 1, traverses its object list, draws the window gadgets, runs hook phase 2, and unlocks. `UpdateEdit` checks that logical window 0 is open, selects its software clip window, redraws edit content and graphs, then turns clipping off. See DOS `src/root/m21FA.c:389-424` and `D:/Prog/simant_recon/src/root/m0250.c:628-636`; the DOS object model is summarized in `D:/Prog/simant_recon/docs/window-model.md:7-35`.
5. **INFERRED** Windows owns non-client frame/caption painting. The top-level frame is a USER-created window; `PaintStuff` uses `BeginPaint`'s client DC and deliberately delegates the top-level/root HWNDs to `DefWindowProc`. The Win16 `win_DrawTitle` path calls `SetWindowText` (audit import), allowing USER to display the caption. SimAnt draws the ribbon client itself and draws the logical window content through `win_DrawWindow`; it does not paint the top-level native frame in this path. For game children, the detailed `win_DrawWindow` body remains open; its best draft calls hooks around visible object drawing and checks `updateRgn` with `RectInRegion` (`evidence/recovery/drafts/win_DrawWindow/50b1198543e4.c:28-66`; target `SIMTWO_MODULE:0xBB96`).

## Invalidation, synchronous updates, and scrolling

- **VERIFIED (Win16 API contract and source calls)** `InvalidateRect(hwnd, rect, erase)` adds the rectangle (or full client when `rect==NULL`) to the update region; `erase` is `FALSE` for most content invalidations and `TRUE` where SimAnt requests a background erase. It schedules painting. `UpdateWindow(hwnd)` immediately sends `WM_PAINT` when an update region exists. `BeginPaint` returns an update-clipped client HDC and validates the region; `EndPaint` completes that paint. `GetUpdateRgn` snapshots a region; `ValidateRgn` removes the supplied part from pending update; `InvalidateRgn` adds it back.
- **VERIFIED** `win_InvalidateObject` gets the logical object's rectangle, increments right and bottom when a ribbon is present, then calls `InvalidateRect(win_hwnd[object>>8], &rect, FALSE)`, so callers request an object-area repaint without erasing its background (`src/recovered/wf_win_InvalidateObject-69cbeedc5b.c:32-46`).
- **VERIFIED** `RedrawWindows` (`SIMANT_MODULE:0x1C68`) creates a `MakeProcInstance` thunk for `MYENUMFUNC` (`SIMANT_MODULE:0x1C38`), enumerates children of `rootWnd`, frees the thunk, and invalidates the ribbon unless it is the requested window (`src/recovered/wf_RedrawWindows-14f4bb1c45.c:19-29`). `MYENUMFUNC` returns TRUE to continue; it invalidates each visible enumerated HWND except the requested HWND, using a null rectangle and no erase (`src/recovered/MYENUMFUNC-6e62bb0fe4.c:11-16`). `RedrawScreen` instead invalidates all of `rootWnd` with erase enabled, then calls `UpdateWindow` (`src/recovered/RedrawScreen.c:1-10`).
- **VERIFIED by resolved disassembly** In `MAINWNDPROC`, the palette refresh path pushes `MYENUMFUNC` at offset `0x1c38`, then calls `EnumChildWindows` on `rootWnd` and frees the thunk (`SIMANT_MODULE:0x2930 + 0x12E7..0x131C`). This resolves a stale `StopSimulation` callback spelling in the current draft.
- **VERIFIED** The Win16 edit update preserves pixels during a scroll: `ScrollEditWindow` computes a tile-pixel delta and calls `ScrollWindow` with the edit tile rectangle as both scroll and clip rectangle; it then snapshots the exposed update region, validates that region, calls `UpdateWindow`, re-invalidates the saved region with `InvalidateRgn`, and deletes it (`src/recovered/wf_ScrollEditWindow-fe9b3200e2.c:38-54`, `ANTEDIT_MODULE:0x113A`). The matched `UpdateEdit` also performs this sequence inline, updates the cache, calls `UpdateWindow`, then draws edit graphs between `MSClipStart`/`MSClipEnd` (`src/recovered/tu_antedit_00F4_OverlayTileSet_27_reviewed-6edb3e7ce8.c:1081-1191`). Its confirmed DOS pair (`root:0250:0E9D`) simply selects the logical clip window and redraws edit content/graphs (`D:/Prog/simant_recon/src/root/m0250.c:628-636`).
- **VERIFIED** `GBoxMove` scrolls a client rectangle, snapshots the resulting update region, validates it, calls `UpdateWindow`, then deletes the region; it does not re-invalidate that saved region in this function (`src/recovered/wf_GBoxMove-31918745e5.c:29-49`, `GR_MODULE:0x4052`).
- **VERIFIED** When the edit cache is invalid, `UpdateEditIfBufInvalid` snapshots and validates the edit HWND's region, calls `UpdateWindow`, then sets `editForce`, regenerates the cache, and clears `editForce` (`src/recovered/tu_antedit_00F4_OverlayTileSet_27_reviewed-6edb3e7ce8.c:1203-1217`).

## Retained data and palettes

- **VERIFIED** The edit canvas is retained in SimAnt memory, not in an HBITMAP or memory DC. `UpdateEditBuffers` allocates `editBuf` once from the edit tile dimensions and locks it while regenerating tile pixels, spider, and balloons (`src/recovered/tu_antedit_00F4_OverlayTileSet_27_reviewed-6edb3e7ce8.c:1297-1372`). `win_DrawEditWindow` checks whether the saved update region intersects `editTileRect`, then locks `editBuf` and sends it through `DoFastBitmap` or `DoFastMonoBitmap` (`src/recovered/tu_antedit_00F4_OverlayTileSet_27_reviewed-6edb3e7ce8.c:1391-1416`). The latter builds a temporary 1-bit `BITMAPINFO`/black-white table and calls `SetDIBitsToDevice` directly on `clipDC` (`src/recovered/wf_DoFastMonoBitmap-4c72c58f17.c:30-69`).
- **INFERRED** The separate map-side `mapBuf` is a SimAnt memory handle sized from `BitmapImageSize` and display plane count, while `InitMapFunctions` allocates a separate `0x2000` "Generated buffer window" handle. These are resource/map caches, not evidence of a GDI surface; exact ownership and invalidation lifetime of `mapBuf` still need tracing. See `src/recovered/data_data_map_buf-8bbe4a1fcb.c:1-2`, best draft `src/recovered/wf_tu_antedit_C19C_InitMapFunctions_4_scaffold-619861a01a.c:161-170`, and admitted `src/recovered/wf_InitMapFunctions-70fb457ea5.c:28-41`.
- **VERIFIED from the complete `evidence/port/audit.json` import inventory** Drawing code uses `SetDIBitsToDevice`; no imports for `BitBlt`, `StretchDIBits`, `CreateCompatibleDC`, or `CreateCompatibleBitmap` appear. The retained edit pixels are a caller-owned DIB byte buffer sent to the current window DC; brushes, pens, and paint regions are short-lived GDI objects. A persistent palette handle and font resources are separate GDI objects.
- **VERIFIED** `PaintStuff` selects and realizes `paletteH` on each paint and restores the previous palette; `MSClipStart` does the same for immediate drawing obtained with `GetDC`, and `MSClipEnd` restores selections and releases that DC (`src/recovered/wf_PaintStuff-4a441706dd.c:48-63`, `src/recovered/MSClipStart-6cff38c0cb.c:17-28`, `src/recovered/wf_MSClipEnd-48c3851864.c:16-29`).
- **VERIFIED constants; INFERRED dispatch** `WM_QUERYNEWPALETTE` is `0x030f`; `WM_PALETTECHANGED` is `0x0311`. The open `MAINWNDPROC` draft shows query-new selecting/realizing `paletteH` on a temporary `GetDC` DC and releasing it. If `RealizePalette` reports changed entries, SimAnt enumerates children with `MYENUMFUNC` to invalidate visible windows and invalidates the ribbon. Palette-changed ignores self-notifications (`wParam==hwnd`); while active it takes the same refresh path. Draft lines: `evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c:860-892`; resolved calls are at `SIMANT_MODULE:0x2930 + 0x12A2..0x1332`.
