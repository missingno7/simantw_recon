## C. Event translation

**Status key.** [VERIFIED] means an admitted exact source or unambiguous target disassembly; [INFERRED] means the best open Win16 draft or a partial packet supports the reading; [UNKNOWN] marks a port-relevant gap. Proposed SDL3 mappings are labelled [INFERRED]. The current Win16 application code is not byte-matched here.

**Boundary summary.** [VERIFIED] The DOS build queues 16-byte input records and exposes them through win_Events/win_GetEvent; the Win16 build instead pumps USER messages and calls its application handlers during DispatchMessage. [VERIFIED] The Win16 win_Events helper drains and dispatches the message queue; it returns only a small “input happened” flag. [INFERRED] DoKeyDown and DoMouse build a short-lived SimAnt object-event record and call DoEvent synchronously. Shared logical windows and object IDs survive the host change; HWNDs and SDL_WindowIDs belong only to the host adapter.

### Registered procedures and pump

- [VERIFIED] InitApplication registers AntRoot, GenericWindow, and RibbonWindow, all with the same MainWndProc callback. Reference: src/recovered/tu_simant_01B6_DoUserButtonUpdate_15_reviewed-db9484741a.c:1066-1104. The target is MAINWNDPROC at SIMANT_MODULE:0x2930 (4,953 bytes); it remains open, so message-specific behaviour below is marked [INFERRED] from its best draft unless a different exact source is cited.
- [INFERRED] WINMAIN is at SIMANT_MODULE:0x3FDA (1,546 bytes). Its best draft calls GetMessage in a loop; TranslateAccelerator gets first refusal, then TranslateMessage and DispatchMessage run for unconsumed messages. The audit confirms the four USER imports; the best draft is evidence/recovery/drafts/WINMAIN/8c89fbd1b287.c:245-255. The loop ends when mainRootWnd becomes zero or GetMessage reports WM_QUIT. It is a blocking message pump, not a frame-by-frame idle loop.
- [VERIFIED] The Win16 _win_Events at SIMTWO_MODULE:0xD040 (112 bytes) repeatedly calls PeekMessage with PM_REMOVE over all HWNDs, sets “acted” for WM_LBUTTONDOWN/UP (0x0201/0x0202) or WM_KEYDOWN Space/Insert (0x0100, VK_SPACE 0x20 or VK_INSERT 0x2D), then TranslateMessage/DispatchMessage for every dequeued message. Source: src/recovered/tu_simtwo_C32E_win_ObjAddr_20_reviewed-cf86811e02.c:192-210. Thus other messages still dispatch while the helper returns false.
- [VERIFIED] The Win16 _win_FlushEvents at SIMTWO_MODULE:0xC20A (76 bytes) removes pending mouse messages 0x0200-0x0209, key/character messages 0x0100-0x0108, and WM_MOUSEACTIVATE 0x0021; it leaves paint, close, timer, and other message classes queued. Source: src/recovered/wf_win_FlushEvents-3010537d93.c:21-29.
- [INFERRED] MYTIMERFUNC at SIMANT_MODULE:0x2440 (973 bytes) is reached on the root window’s WM_TIMER path and performs game/update work. Its best draft calls ProcessPost when network work is pending, conditionally calls DoAntSim, updates windows, and removes queued WM_TIMER messages: evidence/recovery/drafts/MYTIMERFUNC/fc256145b84f.c:581-629. ProcessPost at SIMANT_MODULE:0x1DBF is an open network receive/NetBIOS completion handler, not a mouse/keyboard event translator; its best draft moves completed map/life data and may re-arm receives (evidence/recovery/drafts/ProcessPost/d00424d9c00a.c:48-117).

### Internal event payload and DOS comparison

| Field or routing point | Evidence-backed meaning |
|---|---|
| [INFERRED] Win16 “what” | DoKeyDown’s draft stores a translated key/scancode and an event-state word; DoMouse’s draft stores a message-phase/button-state word. DoEvent switches on the high byte of the word at byte offset +0x0C. Its draft names this word “message”; DoMouse/DoKeyDown name it “object”. Treat it as a SimAnt object/event code, not as WM_* itself. |
| [INFERRED] Win16 “where” | DoMouse uses client x/y and win_FindObject; DoKeyDown obtains cursor screen position, converts it to the top HWND’s client coordinates, then hit-tests. Map HWND → logical index via property INDEX / win_hwnd[] before hit-testing. |
| [UNKNOWN] Win16 “when” | MSG includes USER queue time, but the best DoKeyDown/DoMouse/DoEvent drafts do not copy it into the event record. The record’s exact time field is unresolved. Do not promise DOS-style event timestamps in a direct translation. |
| [INFERRED] Win16 modifiers | keyState is a sampled modifier/toggle word from GetKeyState/GetAsyncKeyState; state carries held-button and input-phase bits and is copied to mouse_state. The exact historic field names remain unproved. |
| [INFERRED] Win16 “window id” | The +0x0C code’s high byte selects the logical event family (0x00 edit, 0x01 map, 0x05 info, 0x12 mode, 0x13 caste, 0x15 history, 0x19 yard, 0x22 map ribbon, 0x23 yard ribbon); the low byte identifies the object. DoEvent routes to ProcEditEvent, ProcMapEvent, ProcInfoEvent, ProcModeEvent, ProcCasteEvent, ProcHistoryEvent, ProcYardEvent, ProcMapRibbonEvent, or ProcYardRibbonEvent. Draft: evidence/recovery/drafts/DoEvent/f1bbc5aa7674.c:45-117. |
| [VERIFIED] DOS event record | DOS m218D.c declares Event as eight 16-bit fields: what, message, x4, modifiers, h, v, code, xE. win_Events consumes at most one queued record per call, recognizes global code 0xFF00 and hover-family 0xFBxx, handles system codes 0xF081-0xF087, then routes ordinary records only when code’s high byte matches the top logical window. Source: D:\Prog\simant_recon\src\root\m218D.c:3-12, 142-225. The main DOS dispatcher then selects Proc* handlers by code & 0xFF00: D:\Prog\simant_recon\src\S19\m384C.c:61-117. |
| [VERIFIED] DOS “when” storage | DOS input enqueue code at root:m1B73.asm:_f_1B73_036E writes BIOS keyboard shift state and BIOS tick count alongside input words; _f_1B73_032E dequeues one 16-byte record. Exact semantic use of each x4/event slot is not fully named in C. |

**SDL3 adapter contract.** [INFERRED] Give each SDL_WindowID a stable mapping to the existing logical SimAnt window ID; hit-test and route through the same object code families. Keep native focus/capture, event timestamps, and rendering invalidation as host concerns. SDL event structs carry the SDL window ID, mouse client coordinates/click count, and keyboard scancode/keycode/modifier/repeat data; they do not supply SimAnt’s logical object ID. Official SDL3 references: https://wiki.libsdl.org/SDL3/SDL_EventType, https://wiki.libsdl.org/SDL3/SDL_MouseButtonEvent, https://wiki.libsdl.org/SDL3/SDL_KeyboardEvent.
