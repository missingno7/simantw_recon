# Portable Windows reference (SimAnt Win16 → SDL3 host contract)

Status: first synthesis, 2026-09-30. It is the specification the SDL3 port starts from; it records what the Win16 build of
SimAnt (SIMANTW.EXE) teaches about hosting the shared SimAnt window/object model on a native multi-window GUI.

Evidence labels used throughout:
- **VERIFIED:** read from byte-exact admitted source or unambiguous original disassembly.
- **INFERRED:** from preserved best drafts or partial call paths.
- **UNKNOWN:** not settled.

Authority rule: the DOS reconstruction (`D:\Prog\simant_recon`, github missingno7/simant_recon) is the behavioural and visual
authority for everything shared: game, simulation, map, database, resources, fonts, drawing semantics, palette/colours, window
contents and the `win_*` object model. This document covers only the Windows-specific delta and the host contract derived from it.

Supporting evidence (durable, in this repository):
- `evidence/port/audit.json`: per-function Windows API use, DOS pairing, call distance (`python tools/port_audit.py`).
- `evidence/port/classification.json`: the final per-function mission class, with the port question per REQUIRED item.
- `evidence/port/sections/*.md`: the full worker sections and their open-question reports, merged below.
- `build/workers/f-host-answers/ANSWERS.md` (in progress at handoff): an Opus analysis answering the open questions from
  the ORIGINAL disassembly of MAINWNDPROC, WINMAIN, win_Open/Close, win_GetEvent, DoMouse, the timer and paint paths.
  Where it contradicts an INFERRED statement below, it wins. Fold it in first (see §H).

## A. Architecture

### A.1 Win16 SimAnt (as shipped)

```
shared SimAnt game / simulation            (same code as DOS: sim, map, db/cache, resources, fonts, gr_* drawing)
        │
shared Maxis win_* / object model          (window records, object records, win_Recalc anchoring, event records,
        │                                   DoEvent dispatch; DOS m20E8/m2505/m21FA/m22BF are the authority)
        │
Win16 adaptation layer                     (Windows-only):
        │  • slot ↔ HWND table: win_hwnd[] / win_handles[] indexed by logicalID >> 8, INDEX window property on each HWND
        │  • native lifetime: win_Open creates-or-reuses a GenericWindow child of rootWnd, shows/raises it; win_Close hides
        │  • message bridge: GetMessage loop (WINMAIN) + PeekMessage pumps (win_Events, win_GetEvent, dialogs),
        │    MAINWNDPROC per-role dispatch → DoMouse / DoKeyDown / DoEvent / MYTIMERFUNC / PaintStuff
        │  • paint bridge: WM_PAINT → PaintStuff (BeginPaint, INDEX → logical window, draw hooks, EndPaint);
        │    immediate drawing outside WM_PAINT through MSClipStart/MSClipEnd (GetDC/ReleaseDC)
        │  • z-order/focus/capture: USER z-order queried live (GetTopWindow/GetNextWindow, BringWindowToTop),
        │    MySetCapture/MyReleaseCapture keep a logical capture owner + OS capture
        │  • shell: AntRoot frame, ribbonBarWnd + rootWnd children, runtime HMENU from db object kind 6, WM_COMMAND
        │    0xFDxx → DoMenuEntry, COMMDLG/DialogBox file dialogs, WinHelp, INI options, 17 ms SetTimer cadence
        │  • GDI adapters: DCs, palettes (SelectPalette/RealizePalette), regions/clipping, bitmap blits
        │
HWND / USER / GDI / message queue (Windows 3.1)
```

Native window structure (VERIFIED for frame/children, INFERRED for game windows):
- one top-level frame `mainRootWnd` (class AntRoot, sized from screen metrics);
- inside it two sibling children, `ribbonBarWnd` (bound to logical slot 0x2200) and `rootWnd`;
- every other logical SimAnt window is a GenericWindow HWND attached to `rootWnd`, created once, then shown/hidden/raised.

### A.2 Proposed SDL3 host

```
shared SimAnt game / simulation            (DOS reconstruction, unchanged)
        │
shared Maxis win_* / object model          (DOS win_*: records, anchoring, stack order, event queue, draw hooks)
        │
portable host-window abstraction           (new, small: §E)
        │  • slot ↔ HostWindow table (replaces win_hwnd[] + INDEX property)
        │  • event adapter: SDL events → the DOS Event record / DoEvent contract (§C)
        │  • invalidate/expose → draw-hook scheduling; retained per-window surfaces (§D)
        │  • logical z-order list owned by the game (like DOS g_5702[]); host raise is a request (§B, §C)
        │  • capture/focus/cursor policy; shell services (menus, file dialogs, options, timers, audio)
        │
SDL_Window / SDL events / portable renderer (DOS palette and resources, logical drawing API)
```

Design decisions supported by the evidence:
1. **Keep the DOS event model.** The host feeds the DOS Event record (code high byte = kind, position, modifiers, window id) and never routes gameplay by native window handle (VERIFIED on both sides).
2. **Keep the DOS window stack as the z-order truth.** Win16 queries USER live, and SDL cannot enumerate z-order, so the game-owned order list is the only portable source; native raises are applied to it (§B/C).
3. **Two presentation options, both compatible with the contract:**
   - one SDL_Window per logical window, mirroring Win16's native multi-window model: each window gets OS chrome and can be moved and resized independently;
   - DOS-style panels composited inside one SDL_Window, the DOS look.
   The host API hides the choice. Win16 proves the shared model survives being split across native windows.
4. **Preserve the logical coordinate space.** Logical window/object rectangles stay in window-client space (DOS). The host converts only at the boundary: pointer position → client coordinates of the hit window; logical rect → native window position/size plus frame (§5).

## B. Window inventory

The full inventory table and lifetimes are in the p1 section below (§B detail); the ownership rules are in A.1.
- Logical IDs map to slots `ID >> 8` (VERIFIED).
- `win_LoadAllWindows` loads the window definitions from database objects. The layout variant is chosen by display type and a desktop height of 480 or more (VERIFIED).
- DOS `win_Open`/`win_Close`/`win_Recalc` (`src/root/m20E8.c`, `m2505.c`) are the behaviour to port. Only the HWND creation, show/hide/raise and frame adjustment in the Win16 `win_Open`/`win_Close` are host-specific.

## C. Event mapping

The concrete Win16 message → SimAnt event → SDL3 table is in the p2 section below. Summary of the contract:
- **Pump.** One SDL event loop replaces:
  - the WINMAIN `GetMessage`/`TranslateAccelerator`/`TranslateMessage`/`DispatchMessage` loop;
  - the nested `PeekMessage` pumps: `win_Events` drains and dispatches everything, returning a narrow input flag; `win_GetEvent` waits for button or key input; dialogs have their own.
  The nested pumps become "pump, then test" helpers in the host. `win_FlushEvents` discards only selected input ranges (VERIFIED difference); keep both semantics.
- **Mapping to SDL3 events:**
  - mouse down/up/move → `SDL_EVENT_MOUSE_BUTTON_DOWN/UP`, `SDL_EVENT_MOUSE_MOTION`;
  - keys → `SDL_EVENT_KEY_DOWN` (+ `SDL_EVENT_TEXT_INPUT` for dialogs);
  - `WM_CLOSE` → `SDL_EVENT_WINDOW_CLOSE_REQUESTED` (with the MenuQuit veto);
  - `WM_PAINT` → `SDL_EVENT_WINDOW_EXPOSED`;
  - `WM_SIZE`/`WM_MOVE` → `SDL_EVENT_WINDOW_RESIZED`/`MOVED`;
  - activation/focus → `SDL_EVENT_WINDOW_FOCUS_GAINED/LOST`;
  - `WM_TIMER` (17 ms) → a host tick.
  The simulation clock stays the DOS `MacTickCount` gate.
- **Polling.** `GetAsyncKeyState` polling (StillDown/ButtonHeld) becomes `SDL_GetMouseState`/`SDL_GetKeyboardState`.

## D. Redraw / invalidation model

Detail in the p4 section below. Lifecycle (VERIFIED where it runs through admitted PaintStuff/RedrawWindows/MYENUMFUNC/GBoxMove):
1. **Damage.** It comes from `InvalidateRect`/`InvalidateRgn` (win_Open, palette changes, state changes), from USER exposure, and from `ScrollWindow` (GBoxMove validates then repaints the exposed strip).
2. **Paint.** `WM_PAINT` goes to PaintStuff: it gets the INDEX property, snapshots the update region, and runs BeginPaint → the logical window's draw hooks → EndPaint.
3. **Immediate drawing.** Some drawing bypasses WM_PAINT: MSClipStart/MSClipEnd take a DC for immediate overlays (cursor, graphs, editor updates).
4. **Palette changes.** They redraw every visible child (EnumChildWindows + MYENUMFUNC).

SDL contract:
- each logical window has a dirty region;
- expose unions into it;
- `host_window_invalidate` marks it;
- the frame step calls the DOS draw hooks for the dirty parts, then presents;
- immediate overlays draw into the same retained surface and mark it dirty.

A retained per-window surface (like the Win16 edit buffer) makes expose cheap. The GDI layer itself is not ported: the SDL renderer implements the shared logical drawing API (`gr_*`, `font_*`, bitmap/object drawing) with DOS palette and resources.

## E. Host-window API proposal

A small C API, derived from what the Win16 adapter actually needed (every call below has a Win16 counterpart in A.1):

```c
typedef struct HostWindow HostWindow;          /* one per logical SimAnt window slot (ID >> 8) */

/* lifetime: created once per slot, then shown/hidden (Win16 win_Open/win_Close reuse) */
HostWindow *host_window_create(int slot, const Rect *client, unsigned flags); /* flags: titled, resizable, tool/owned, modal */
void        host_window_destroy(HostWindow *w);                              /* shutdown only (CleanUp) */
void        host_window_show(HostWindow *w, int visible);
void        host_window_raise(HostWindow *w);           /* BringWindowToTop; the game order list is updated by the caller */
void        host_window_set_title(HostWindow *w, const char *title);         /* win_DrawTitle → SetWindowText */
void        host_window_set_rect(HostWindow *w, const Rect *client);          /* logical client rect → native placement */
void        host_window_get_rect(HostWindow *w, Rect *client);

/* painting */
void        host_window_invalidate(HostWindow *w, const Rect *r);             /* InvalidateRect; NULL = whole */
void        host_window_begin_draw(HostWindow *w);      /* immediate drawing outside expose (MSClipStart) */
void        host_window_end_draw(HostWindow *w);        /* (MSClipEnd) */
void        host_present_dirty(void);                   /* WM_PAINT/PaintStuff: run draw hooks for dirty regions, present */

/* input */
int         host_pump_events(int wait);                 /* WINMAIN loop / win_Events; feeds the DOS Event queue */
void        host_flush_input(unsigned mask);            /* win_FlushEvents */
void        host_capture_mouse(HostWindow *w);          /* MySetCapture (logical owner + OS capture); NULL releases */
void        host_set_cursor(int cursor_id);             /* the 7 Win16 tool cursors; the DOS map cursor stays a game overlay */
void        host_get_mouse(int *x, int *y, unsigned *buttons, HostWindow **over); /* GetMousePos/StillDown/ButtonHeld */

/* shell */
void        host_set_menu(const MenuSpec *menu);        /* runtime menu from db object kind 6 (InitMenu) */
int         host_file_dialog(int save, char *path, int cap);                  /* GetOpenFileName/GetSaveFileName */
void        host_timer(unsigned period_ms, int enable); /* 17 ms tick; Stop/RestartSimulation */
int         host_options_get(const char *key, int def); /* INI: 6 options + 16 user-button assignments */
void        host_options_set(const char *key, int value);
```

The rest stays in shared code, with the DOS version as the authority: window records, anchoring (win_Recalc), the stack order, hit testing, event dispatch, draw hooks, menus' command semantics (ProcMenu), dialogs' logic, audio events.

## F. Windows-only knowledge gaps that matter to the SDL3 port

Consolidated from the section reports; ordinary unmatched game functions are not gaps. Most are expected to close with
`build/workers/f-host-answers/ANSWERS.md` (original-disassembly answers):
1. **Complete MAINWNDPROC dispatch per window role.** Which messages reach SimAnt, WM_ERASEBKGND and background erase, whether right-button messages reach DoMouse, and which button-up releases capture.
2. **Timer ordering.** The first-tick order between the WINMAIN SetTimer callback, StopSimulation/RestartSimulation and MYTIMERFUNC, and whether the simulation ever runs outside the pump.
3. **Auto-close.** Whether Win16 keeps DOS's close-front-window-on-outside-click rule (record flag +0x1C bit 0). DOS is the authority either way.
4. **Logical window slots.** The purpose of every slot, including 0x2300 and the DOS-only IDs 0x1600/0x1F00/0x2100, and which windows are titled, resizable or modal. This decides SDL window flags and native-window versus panel presentation.
5. **Resize policy.** Win16 re-lays out window 0 (edit) and the root/bar hosts; other windows follow the DOS anchor rules (win_Recalc) or stay fixed.
6. **Coordinate conventions.** Window-local rects and inclusive versus half-open edges, for the renderer.
7. **Retained buffers.** Ownership and invalidation of editBuf/mapBuf/lastMapMapBuf; this decides persistent SDL surfaces.
8. **Assets.** The menu label → ProcMenu command map (db object kind 6), and the 7 cursor bitmaps and hotspots for SDL cursors.
9. **Product decisions, not reverse-engineering questions.** Native multi-window versus in-app panels, portable help, and DDE (obsolete).

## Evidence convention

`[VERIFIED]` means read from an admitted exact source or unambiguous target disassembly/import evidence. `[INFERRED]` means taken from a preserved open-function draft, caller/callee evidence, or a supported cross-version mapping. `[UNKNOWN]` means the inspected evidence does not settle the field. ## Shared native-window contract

- **[VERIFIED] Logical identity:** normal game HWNDs are stored in `win_hwnd[ID >> 8]`; `win_Open` is passed packed IDs such as `0x0000`, `0x0100`, etc. `SetProp(hwnd,"INDEX",ID)` binds the full logical ID to each generic HWND. Evidence: `win_Open` at `SIMTWO_MODULE:CA2E` (1385 bytes; draft `evidence/recovery/drafts/win_Open/340a8dee76c6.c:89-230`), `INDIRECTDLGPROC` at `SIMTWO_MODULE:DDD2`, and exact `win_IsWinInFront` in `src/recovered/win_IsWinInFront-c38b403794.c:10-31`.
- **[VERIFIED] Shared classes:** `InitApplication` at `SIMANT_MODULE:3DD0` (exact source `src/recovered/InitApplication-a2dc0a1ce1.c:41-79`) registers `AntRoot`, `GenericWindow`, and `RibbonWindow`; all three use `MainWndProc`. `AntRoot` has class style `0`, icon resource `"SimAnt"`, arrow cursor, background `0x0d`; `GenericWindow` and `RibbonWindow` use class style `0x1008` (`CS_BYTEALIGNCLIENT | CS_DBLCLKS`), no class menu, and backgrounds `6` and stock object `1`, respectively.
- **[VERIFIED] Frame hierarchy:** `InitInstance` at `SIMANT_MODULE:3C8A` (exact source `src/recovered/tu_simant_01B6_DoUserButtonUpdate_15_reviewed-db9484741a.c:1024-1104`, literals at `:356-366`) creates `mainRootWnd` as top-level `AntRoot` style `0x02CF0000` (`WS_CLIPCHILDREN | WS_OVERLAPPEDWINDOW`), then creates `rootWnd` and `ribbonBarWnd` as `AntRoot`/`RibbonWindow` children of `mainRootWnd`, each style `0x52000000` (`WS_CHILD | WS_VISIBLE | WS_CLIPCHILDREN`). **[VERIFIED]** `mainRootWnd` and `rootWnd` are separate globals rather than logical slots; **[INFERRED]** the best `WINMAIN` draft also binds `ribbonBarWnd` into `win_hwnd[0x22]` for logical ID `0x2200` (`evidence/recovery/drafts/WINMAIN/8c89fbd1b287.c:175-190`).
- **[INFERRED] Generic HWND kind:** `win_Open` calls `CreateWindow("GenericWindow", "Generic Window", style, ..., rootWnd, ...)`; target style construction only sets low-order style bits and never sets `WS_CHILD` (`0x40000000`) or `WS_POPUP` (`0x80000000`). Under Win16 `CreateWindow` conventions this is an owned, overlapped top-level window associated with `rootWnd`, rather than a child window. Evidence: `win_Open` draft above and Win16 constants in `toolchain/sdk310/INC/WINDOWS.H:2934,2936,2978-2986,3009-3010,3328-3330`. SDK semantic reference: [Windows 3.1 SDK Programming Guide](https://bitsavers.trailing-edge.com/pdf/microsoft/windows_3.1/Microsoft_Windows_3.1_SDK_1992/PC28919-0492_Guide_to_Programming_199204.pdf) (child windows use `WS_CHILD`); [CreateWindow reference](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createwindoww) (parent argument supplies parent/owner context).
- **[INFERRED] Open/show/reuse:** `win_LoadAllWindows` at `SIMTWO_MODULE:C806` loads metadata and clears HWND slots; HWNDs are created lazily by `win_Open` when a slot is empty. A populated visible slot is brought to top; a populated hidden slot is repositioned, shown, invalidated, and updated; an empty slot is created, tagged with `INDEX`, then shown. Evidence: `evidence/recovery/drafts/win_LoadAllWindows/fcc0028f9bdb.c` and `evidence/recovery/drafts/win_Open/340a8dee76c6.c:89-230`; USER imports in `build/context/win_Open.json` include `CreateWindow`, `SetProp`, `ShowWindow`, `BringWindowToTop`, `SetWindowPos`, `InvalidateRect`, and `UpdateWindow`.
- **[INFERRED] Object loading and layout:** `win_LoadWindow` at `SIMTWO_MODULE:C662` loads the resource-backed data for a logical ID and initializes its object/pointer state; `win_Recalc` at `SIMTWO_MODULE:E6E2` recalculates logical object rectangles and anchor/automatic sizing before `win_Open` applies native frame/ribbon metric adjustments. Evidence: drafts `evidence/recovery/drafts/win_LoadWindow/ae79989982f6.c`, `evidence/recovery/drafts/win_Recalc/868bd0db1b17.c`, and `evidence/recovery/drafts/win_Open/340a8dee76c6.c:89-230`.
- **[INFERRED] Close is hide/reuse:** `win_Close` at `SIMTWO_MODULE:CF98` (168 bytes; draft `evidence/recovery/drafts/win_Close/cfc32202bfaa.c:28-58`) clears the logical open flag and calls `ShowWindow(hwnd, SW_HIDE)`; it selects a remaining top window and sends `WM_NCACTIVATE (0x0086)` via `SendMessage`. The `WM_SIZE (0x0005)` draft handles frame/root/ribbon geometry and the edit window; other logical window resize policy is not established. Evidence: `evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c:301-401`; target is open at `SIMANT_MODULE:2930` (4953 bytes). Treat all detailed `MainWndProc` behavior as inferred until exact source is admitted.
- **[VERIFIED] Hook table:** `InitApplicationWindows` exact source registers 11 hook mappings after `win_LoadAllWindows`: `0x000 win_DrawEditWindow`, `0x0100 win_DrawMapWindow`, `0x1500 win_DrawHistoryWindow`, `0x1200 win_DrawModeWindow`, `0x1300 win_DrawCasteWindow`, `0x1900 win_DrawYardWindow`, `0x0500 win_DrawInfoWindow`, `0x1E00 win_DrawPictureWindow`, `0x0400 win_DrawEndGameWindow`, `0x1D00 win_DrawExamineWindow`, `0x1800 win_DrawScoreWindow`. - **[VERIFIED] DOS manager:** DOS `win_LoadWindow`, `win_LoadAllWindows`, `win_Open`, `win_Close`, and `win_SetWinDrawHook` are in `D:\Prog\simant_recon\src\root\m20E8.c:36-71,96-140,207-255,259-289,351-354`. ## Lifetime narrative

**[VERIFIED]** Startup registers the three classes and constructs the main frame plus root and ribbon child HWNDs; the application window initialization loads resource-backed logical-window metadata and installs draw hooks. **[INFERRED]** `WINMAIN` later binds the ribbon child HWND to logical slot 34, so this slot is a special child-window alias. **[INFERRED]** Other logical windows remain data objects until first opened; `win_Open` then creates or reuses a `GenericWindow`, tags it with its logical ID, shows it, and places it in native z-order. **[INFERRED]** Closing a normal logical window hides it and marks its resource-backed record closed, retaining the HWND for reuse; the application frame's accepted close follows a distinct application shutdown path. **[VERIFIED]** DOS instead pushes and removes logical windows in its own active stack, clips/redraws on close, and has no native ownership, visibility, focus, or HWND destruction lifecycle.

## C. Event translation

**Status key.** [VERIFIED] means an admitted exact source or unambiguous target disassembly; [INFERRED] means the best open Win16 draft or a partial packet supports the reading; [UNKNOWN] marks a port-relevant gap. Proposed SDL3 mappings are labelled [INFERRED]. The current Win16 application code is not byte-matched here.

**Boundary summary.** [VERIFIED] The DOS build queues 16-byte input records and exposes them through win_Events/win_GetEvent; the Win16 build instead pumps USER messages and calls its application handlers during DispatchMessage. [VERIFIED] The Win16 win_Events helper drains and dispatches the message queue; it returns only a small “input happened” flag. [INFERRED] DoKeyDown and DoMouse build a short-lived SimAnt object-event record and call DoEvent synchronously. Shared logical windows and object IDs survive the host change; HWNDs and SDL_WindowIDs belong only to the host adapter.

### Registered procedures and pump

- [VERIFIED] InitApplication registers AntRoot, GenericWindow, and RibbonWindow, all with the same MainWndProc callback. Reference: src/recovered/tu_simant_01B6_DoUserButtonUpdate_15_reviewed-db9484741a.c:1066-1104. The target is MAINWNDPROC at SIMANT_MODULE:0x2930 (4,953 bytes); it remains open, so message-specific behaviour below is marked [INFERRED] from its best draft unless a different exact source is cited.
- [INFERRED] WINMAIN is at SIMANT_MODULE:0x3FDA (1,546 bytes). Its best draft calls GetMessage in a loop; TranslateAccelerator gets first refusal, then TranslateMessage and DispatchMessage run for unconsumed messages. The audit confirms the four USER imports; the best draft is evidence/recovery/drafts/WINMAIN/8c89fbd1b287.c:245-255. The loop ends when mainRootWnd becomes zero or GetMessage reports WM_QUIT. It is a blocking message pump, not a frame-by-frame idle loop.
- [VERIFIED] The Win16 _win_Events at SIMTWO_MODULE:0xD040 (112 bytes) repeatedly calls PeekMessage with PM_REMOVE over all HWNDs, sets “acted” for WM_LBUTTONDOWN/UP (0x0201/0x0202) or WM_KEYDOWN Space/Insert (0x0100, VK_SPACE 0x20 or VK_INSERT 0x2D), then TranslateMessage/DispatchMessage for every dequeued message. Source: src/recovered/tu_simtwo_C32E_win_ObjAddr_20_reviewed-cf86811e02.c:192-210. Thus other messages still dispatch while the helper returns false.
- [VERIFIED] The Win16 _win_FlushEvents at SIMTWO_MODULE:0xC20A (76 bytes) removes pending mouse messages 0x0200-0x0209, key/character messages 0x0100-0x0108, and WM_MOUSEACTIVATE 0x0021; it leaves paint, close, timer, and other message classes queued. Source: src/recovered/wf_win_FlushEvents-3010537d93.c:21-29.
- [INFERRED] MYTIMERFUNC at SIMANT_MODULE:0x2440 (973 bytes) is reached on the root window’s WM_TIMER path and performs game/update work. Its best draft calls ProcessPost when network work is pending, conditionally calls DoAntSim, updates windows, and removes queued WM_TIMER messages: evidence/recovery/drafts/MYTIMERFUNC/fc256145b84f.c:581-629. ProcessPost at SIMANT_MODULE:0x1DBF is an open network receive/NetBIOS completion handler, not a mouse/keyboard event translator; its best draft moves completed map/life data and may re-arm receives (evidence/recovery/drafts/ProcessPost/d00424d9c00a.c:48-117).

# Z-order, activation, focus, capture, and cursor

**Evidence key:** **VERIFIED** means an admitted Win16 source or exact DOS source/model. **INFERRED** means a best Win16 draft or incomplete DOS cursor source. **UNKNOWN** marks a behavior the available evidence does not settle.

## Ordering and front tests

- **VERIFIED — DOS authority:** DOS keeps its own logical order in `g_5702[]`, with the front window at `[0]` and `0x8000` as the terminator. `win_IsWinInFront(win)` is only `g_5702[0] == win` (`simant_recon/src/root/m22BF.c:501-506`, DOS address `root:22BF:0A22`; global noted in `simant_recon/docs/window-model.md:32-35`). `f_1E57_00B1` moves a window ID to `[0]` and removes its old occurrence (`simant_recon/src/root/m1E57.c:74-91`). Closing removes an ID from the stack (`clip_KillWin`, `m1E57.c:95-110`).
- **VERIFIED — Win16 delta:** The Win16 `win_*` layer maps a packed game window ID to `win_hwnd[id >> 8]`; `win_ToTop(id)` passes that HWND to `BringWindowToTop` (`src/recovered/win_ToTop.c:1-7`, `SIMTWO_MODULE:D41E`). USER's `BringWindowToTop` also activates a top-level window (or a child's top-level parent), so Win16 raising couples z-order and activation ([BringWindowToTop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-bringwindowtotop)). `INDEX` window properties map an HWND back to the game ID (`src/recovered/win_IsWinInFront-c38b403794.c:10-31`, `SIMTWO_MODULE:C19E`).
- **VERIFIED — Win16 enumeration:** `GetTopWindow(rootWnd)` starts at USER's top child; relation `2` (`GW_HWNDNEXT`) walks down the Z order, relation `3` (`GW_HWNDPREV`) walks up, and relation `4` (`GW_OWNER`) obtains an owner. `MyGetTopWindow` skips invisible HWNDs and returns the owner of the first visible window when it has one (`src/recovered/wf_MyGetTopWindow-8cee2c18ed.c:12-31`). `win_IsWinInFront(id)` performs the same visible-window/owner normalization, then compares `GetProp(hwnd,"INDEX")` with `id` (`win_IsWinInFront-c38b403794.c:10-31`). These are USER relationships, not comparisons against a second Win16 game stack ([GetTopWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-gettopwindow), [GetWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindow)).
- **VERIFIED — Win16 cycle helper:** `_DoNextWindow` walks relation `2` to the last HWND, then relation `3` past owned or hidden HWNDs, and raises the first remaining window (`SIMANT_MODULE:182C`; admitted body in `src/recovered/tu_simant_01B6_DoUserButtonUpdate_15_reviewed-db9484741a.c:846-860`). **INFERRED:** The open `win_Open` draft adds a system-menu “Next” item with Ctrl+F6, and the open `MAINWNDPROC` draft handles `WM_SYSCOMMAND`/`SC_NEXTWINDOW` (`0x0112`/`0xF040`) by another visible/unowned walk (`evidence/recovery/drafts/win_Open/340a8dee76c6.c:203-218`; `evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c:722-740`).
- **VERIFIED — Win16 exposure is geometric:** `win_IsWinExposed(id)` converts the HWND client rectangle to screen coordinates and returns true only if its intersection with `GetWindowRect(rootWnd)` equals the full client rectangle (`src/recovered/wf_win_IsWinExposed-22083a86a9.c:30-51`, `SIMTWO_MODULE:C102`). It does **not** ask whether another sibling obscures the window. DOS has no matching OS-occlusion query in the recovered stack model.

## Activation, focus, opening, and closing

- **VERIFIED — focus API inventory:** The Win16 image imports `SetFocus` once in `MAINWNDPROC`; the audit finds no `SetActiveWindow`, `GetActiveWindow`, or `GetFocus` import (`build/port/audit.json`; `MAINWNDPROC` target at `SIMANT_MODULE:2930`). **INFERRED:** The best draft uses private `activeAppFlag` state and does not query a USER-focused SimAnt child to decide game state.
- **INFERRED — app activation:** The best `MAINWNDPROC` draft handles `WM_ACTIVATEAPP` (`0x001C`). On activation it sets `activeAppFlag`, restores the remembered non-client-active window (`WM_NCACTIVATE`, `0x0086`), calls `SetFocus(rootWnd)`, and restores a saved capture if its HWND is visible and the main window is not iconic. On deactivation it releases native capture, saves/disables sound options, changes timer cadence and palette state, and remembers a system cursor (`evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c:435-504`). This is app-level activation, not a `SetActiveWindow`/`GetFocus` policy for each logical window.
- **INFERRED — click-to-activate policy:** In the same draft, for a left-button `WM_MOUSEACTIVATE` (`0x0021`) on a non-root HWND, the handler checks bit `0x40` in the current top window record. With a valid top-window `INDEX` and the bit clear it raises the clicked HWND, sends `WM_NCACTIVATE(1)`, and returns `2` (`MA_ACTIVATEANDEAT`); otherwise it returns `3` (`MA_NOACTIVATE`) (`MAINWNDPROC` draft lines 541-556). The return meanings follow USER's message contract ([WM_MOUSEACTIVATE](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mouseactivate)).
- **INFERRED — show/hide:** The open `_win_Open` draft maps an already-visible logical window to `BringWindowToTop`; it positions and shows an existing hidden HWND, or creates a `GenericWindow`, stores its game ID as `INDEX`, raises it, shows it, invalidates it, and updates it (`SIMTWO_MODULE:CA2E`; `evidence/recovery/drafts/win_Open/340a8dee76c6.c:89-229`). The open `_win_Close` draft clears the game open bit and uses `ShowWindow(hwnd,0)` to hide but retain the HWND; it then raises the next visible/normalized window and posts `WM_NCACTIVATE` (`0x0086`) (`SIMTWO_MODULE:CF98`; `evidence/recovery/drafts/win_Close/cfc32202bfaa.c:28-58`). `MAINWNDPROC` draft maps `WM_CLOSE` (`0x0010`) on an indexed game HWND to `win_Close`; closing `mainRootWnd` instead follows the quit prompt path (`MAINWNDPROC` draft lines 403-422). `win_Zoom` is admitted and uses `ShowWindow(hwnd,3)` (`src/recovered/win_Zoom.c:1-7`).
- **VERIFIED — DOS auto-close contract:** On a DOS click, `f_218D_0451` closes the front window if the click is outside its window rectangle and its record bit `+0x1C & 1` is set. If the front record's `+0x1C & 0x40` is clear, it finds the stack window containing the click and calls `f_20E8_0725` to bring it forward; that helper closes a different front window first when its bit `+0x1C & 1` is set (`simant_recon/src/root/m218D.c:233-257`, DOS address `root:218D:0451`; `m20E8.c:293-309`, DOS address `root:20E8:0725`).
- **UNKNOWN — Win16 auto-close equivalence:** The Win16 open/close and main-procedure drafts show USER visibility, activation, and hide/show behavior, but do not prove that the DOS bit-`1` outside-click auto-close rule is reproduced. The SDL port should retain the DOS rule in shared window logic unless later Win16 evidence establishes a deliberate difference; do not infer auto-close from bit `0x40` in `WM_MOUSEACTIVATE`.
- **VERIFIED — custom versus native dialogs:** `DoScenario` opens logical window `0x200`, takes capture, flushes queued events, and runs a synchronous `win_GetEvent`/abort/Enter loop before closing the window (`src/recovered/wf_DoScenario-496dc7a0ac.c:44-87`). **INFERRED:** This is a modeless HWND under the game manager but modal to that game routine. **VERIFIED — separate native path:** `_FileSelect` imports USER `DialogBox`, and `OPENDLG`/`SAVEASDLG` use dialog-procedure APIs; file selection is a genuine USER dialog path (`build/port/audit.json`).

## Invalidation, synchronous updates, and scrolling

## Contract boundary

[VERIFIED] The DOS implementation is the behavior authority for the shared window/object model. Its window record carries the client rectangle, object count, layout parameters, flags, and object-record pointers; object records carry anchoring modes, type, visibility/selection/dirty flags, and drawing data (DOS docs/window-model.md:7-35; exact DOS routines src/root/m20E8.c:207,259, src/root/m21FA.c:389, and src/root/m22BF.c:483,501).

[INFERRED] The Win16 adapter adds an HWND mapping per window bucket: win_Open indexes win_handles/win_hwnd with objectNumber >> 8, creates or reuses a GenericWindow, attaches its full SimAnt ID under the INDEX property, applies native geometry/menu/show state, then invalidates and updates it. The preserved best draft records these paths at evidence/recovery/drafts/win_Open/340a8dee76c6.c:89-227; _win_Open is still an open byte-recovery target, but the window-mapping answer is present.

[INFERRED] The Win16 message bridge uses GetMessage, accelerator handling, translation, and dispatch in that order (evidence/recovery/drafts/WINMAIN/8c89fbd1b287.c:250-255). win_GetEvent pumps PeekMessage/TranslateMessage/DispatchMessage and ends on left-button down/up or Space/- keydown, then derives the target SimAnt object from capture/INDEX and the pointer hit test (evidence/recovery/drafts/win_GetEvent/bec22cc90795.c:102-190).

[VERIFIED] The Win16 SDK header assigns WM_SIZE=0x0005, WM_PAINT=0x000F, WM_QUIT=0x0012, WM_MOUSEACTIVATE=0x0021, WM_GETMINMAXINFO=0x0024, WM_NCRBUTTONDOWN=0x00A4, WM_KEYDOWN=0x0100, WM_TIMER=0x0113, and left-button down/up 0x0201/0x0202 (toolchain/sdk300/INC/WINDOWS.H:1783,1792,1795,1809,1812,1842,1850,1863,1875-1876).

[INFERRED] The main-window best draft routes these messages through resize, activation/capture, timer, keyboard/mouse, palette, and paint paths (evidence/recovery/drafts/MAINWNDPROC/2512b5b9e4d8.c:292-887).

[VERIFIED] Painting is driven by the HWND update region: PaintStuff gets the INDEX property, snapshots the update region, brackets indexed-window drawing with BeginPaint/EndPaint, and restores GDI state (src/recovered/wf_PaintStuff-4a441706dd.c:39-63). GBoxMove uses ScrollWindow, collects and validates the exposed region, forces UpdateWindow, then deletes the temporary region (src/recovered/wf_GBoxMove-31918745e5.c:44-49).

[INFERRED PORT CONSTRAINT] SDL must preserve the resulting image; it may implement the scroll by copying retained pixels or by redrawing the whole dirty area.

[VERIFIED] Capture has both a logical SimAnt owner and an OS owner: MySetCapture stores captureWnd, requests USER capture only while active and not iconic, and accepts an OS capture handle only if it has INDEX; MyReleaseCapture clears the logical owner and calls ReleaseCapture while active (src/recovered/MySetCapture-a20ced370b.c:16-25, src/recovered/MyReleaseCapture.c:5-10, src/recovered/MyGetCapture.c:1-5).
